# ETL Pipelines Design

**Date**: 2026-02-26
**Branch**: `feat/etl-pipelines`
**Status**: Approved

## Overview

Add ETL pipeline support to DataWeaver. Users connect two data sources, define column mappings with transformations (assisted by an LLM), and export executable SQL scripts. DataWeaver generates the SQL but never executes writes — the user runs the scripts externally.

## Use Case

Cross-system sync between independent databases (e.g., CRM to analytics warehouse, app DB to reporting DB). DataWeaver's semantic catalog already knows both schemas, making it the ideal place to define and maintain these mappings.

## Data Model

### EtlPipeline

| Field | Type | Description |
|-------|------|-------------|
| id | String (cuid) | Primary key |
| name | String | Pipeline name |
| description | String? | Optional description |
| sourceDataSourceId | String | FK to DataSource (read from) |
| destDataSourceId | String | FK to DataSource (write to) |
| status | Enum: draft, ready | Pipeline readiness |
| createdAt | DateTime | |
| updatedAt | DateTime | |

### EtlMapping

| Field | Type | Description |
|-------|------|-------------|
| id | String (cuid) | Primary key |
| pipelineId | String | FK to EtlPipeline |
| name | String | Mapping name (e.g., "Orders -> Sales") |
| sourceQuery | String | Full SELECT SQL (extraction + transformation) |
| destTable | String | Target table name in destination DB |
| columnMappings | Json | `{ sourceAlias: destColumn }` pairs |
| conflictStrategy | Enum: insert, upsert, replace | How to handle existing rows |
| orderIndex | Int | Execution order within pipeline |
| createdAt | DateTime | |
| updatedAt | DateTime | |

## UI Design

### Pipeline List Page (`/pipelines`)

Card grid showing saved pipelines with name, source/dest badges, status, and mapping count. Same layout pattern as `/connections` and `/dashboards`.

### Pipeline Editor Page (`/pipelines/[id]`)

Three-panel layout:

```
┌──────────────────────┬──────────────────┬───────────────────┐
│                      │                  │                   │
│   XY Flow Canvas     │  Detail Panel    │   Chat Sidebar    │
│                      │                  │                   │
│  Source tables on     │ Source query      │  Natural language │
│  left, destination   │ (code editor)    │  input to LLM     │
│  on right, edges     │                  │                   │
│  show mappings       │ Column mapping   │  LLM creates and  │
│                      │ table            │  updates mappings  │
│  Click edge/node to  │                  │  via tool calls    │
│  open detail panel   │ Conflict strategy│                   │
│                      │ dropdown         │                   │
└──────────────────────┴──────────────────┴───────────────────┘
```

- **Canvas**: XY Flow with source table nodes (left) and destination table nodes (right). Edges represent mappings. Drag to create new mappings.
- **Detail Panel**: Edit selected mapping — source SQL editor, column mapping table, conflict strategy.
- **Chat Sidebar**: LLM assistant scoped to both schemas. Describe mappings in natural language.

### Toolbar

- **Suggest Mappings** button: triggers LLM to analyze both schemas and propose initial mappings for all tables with matching/similar columns. User reviews and accepts/rejects each.
- **Export** button: opens export modal.

### Export Modal

Full SQL script with comments identifying source/destination connections. Tabs per mapping for individual review. Actions: copy to clipboard, download as `.sql`. Preview button runs the SELECT part read-only against the source.

## LLM Integration

### System Prompt

Includes both source and destination schemas (from catalog metadata). Instructs the LLM to help build ETL mappings.

### Agent Tools

| Tool | Description |
|------|-------------|
| `createMapping` | Create a new mapping (sourceQuery, destTable, columnMappings, conflictStrategy) |
| `updateMapping` | Modify an existing mapping |
| `deleteMapping` | Remove a mapping |
| `previewQuery` | Run read-only SELECT against source to validate extraction |
| `generateExportSql` | Produce final INSERT/UPSERT scripts for all mappings |

### Auto-Map Flow

1. User clicks "Suggest Mappings" button
2. System sends both schemas to LLM with instruction to find matching tables/columns
3. LLM calls `createMapping` for each suggested pair
4. Mappings appear on canvas for user review

## SQL Export Format

```sql
-- Pipeline: CRM -> Warehouse
-- Generated by DataWeaver on 2026-02-26
-- Source: postgresql://crm_prod:5432/crm
-- Destination: postgresql://analytics:5432/warehouse

-- Mapping 1: Orders -> Sales Summary
-- Strategy: UPSERT on (customer_id)
INSERT INTO sales_summary (customer_id, revenue, num_orders)
SELECT customer_id, SUM(amount), COUNT(*)
FROM orders
WHERE created_at > NOW() - INTERVAL '30 days'
GROUP BY customer_id
ON CONFLICT (customer_id) DO UPDATE SET
  revenue = EXCLUDED.revenue,
  num_orders = EXCLUDED.num_orders;
```

## Transformation Support

Full SQL power in sourceQuery:
- Column renaming and type casting
- Simple expressions (UPPER, LOWER, COALESCE, concatenation)
- Aggregations (SUM, COUNT, AVG, MIN, MAX, GROUP BY, HAVING)
- Computed columns (arithmetic, CASE expressions)
- JOINs across source tables
- Subqueries and CTEs
- Window functions

## Architecture Decisions

1. **SQL-only export**: DataWeaver generates scripts but never executes writes. Zero write risk.
2. **Direct connection for preview**: Preview SELECTs use existing read-only query execution path against the source.
3. **LLM-assisted, not LLM-dependent**: All mappings are manually editable. The LLM accelerates creation but isn't required.
4. **Per-mapping conflict strategy**: Each mapping independently chooses insert/upsert/replace.
5. **Ordered execution**: Mappings have an orderIndex for dependency ordering (e.g., dimension tables before fact tables).
